Overview

SETTL is a Solana-based AUDD payment gateway. Merchants receive payments into an escrow vault PDA and funds are released daily at 6am UTC, net of a 1.5% fee.

You can integrate SETTL into your own platform in two ways:

  • Redirect / link — Create a payment session via API, send the checkout_url to your customer. They pay on the SETTL checkout page.
  • Webhook + poll — After creating a session, poll /api/pay/status/:ref or listen for the deposit.confirmed webhook to confirm payment server-side before fulfilling the order.

Base URL

https://your-settl-domain.com

Authentication

All programmatic endpoints use an API key in the request header:

x-api-key: sk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Generate API keys from the API keys page.

Checkout integration

The SETTL checkout page works for any payment session, regardless of how it was created — directly from the SETTL dashboard, or programmatically via API key. Your customers see the same branded experience either way.

Step 1 — Create a payment session

POST /api/pay/charge

Call this from your server (not the browser) using your API key.

# Create a payment session curl -X POST https://your-settl-domain.com/api/pay/charge \ -H "x-api-key: sk_live_..." \ -H "Content-Type: application/json" \ -d '{"amount": 25.00, "message": "Order #1234"}'

Request body

FieldTypeDescription
amountnumberAmount in AUDD (e.g. 25.00). Leave out for open amount.
messagestringOrder reference shown on checkout page. Optional.
memostringOn-chain memo included in the Solana transaction. Optional.

Response

{ "session_id": "uuid", "reference": "base58-public-key", // unique per payment "checkout_url": "https://your-settl.com/pages/checkout.html?ref=...", "url": "solana:vault?spl-token=...&reference=...&amount=25", "amount": 25.00, "merchant_name": "Your Store" }

Step 2 — Redirect customer to checkout

Send the customer to checkout_url. They can scan the QR with Phantom, Backpack, or any Solana wallet — or use the manual vault address.

// Node.js / Express example const session = await createSettlSession({ amount: 25.00, message: orderId }); res.redirect(session.checkout_url);
The checkout page is universal — it works for SETTL merchants, API integrations, and embedded iframes. The page auto-detects the session from the ?ref= query parameter and polls until payment is confirmed.

Step 3 — Confirm payment server-side

Never rely on the client redirecting back to confirm payment. Always verify server-side using one of:

  • Poll — GET /api/pay/status/:reference until {"status":"confirmed"}
  • Webhook — Listen for the deposit.confirmed event (recommended for production)
GET /api/pay/status/:reference
# Poll payment status (no auth needed) curl https://your-settl.com/api/pay/status/4ioangUTMFq... # Response { "status": "confirmed", "tx": "3pP6cANT..." } # or { "status": "pending" }

API keys

API keys allow your server to create payment sessions without a SETTL account session. Generate them from API keys.

API keys are secret — treat them like passwords. Never include them in frontend JavaScript or mobile apps. Always call SETTL from your server backend.

Full Node.js integration example

// server.js — your own backend const SETTL_API_KEY = process.env.SETTL_API_KEY; // sk_live_... const SETTL_BASE = 'https://your-settl-domain.com'; async function createPayment(orderId, amount) { const res = await fetch(`${SETTL_BASE}/api/pay/charge`, { method: 'POST', headers: { 'x-api-key': SETTL_API_KEY, 'Content-Type': 'application/json', }, body: JSON.stringify({ amount, message: `Order ${orderId}`, }), }); const session = await res.json(); // Redirect customer to checkout return session.checkout_url; } // Later — verify payment before fulfilling order async function checkPayment(reference) { const res = await fetch(`${SETTL_BASE}/api/pay/status/${reference}`); const data = await res.json(); return data.status === 'confirmed'; }

Python example

import requests SETTL_API_KEY = "sk_live_..." Webhooks

SETTL sends an HTTP POST to your endpoint when payment events occur. Configure endpoints from the Webhooks page.

Request format

Every webhook request includes these headers:

HeaderValueDescription
Content-Typeapplication/jsonAlways JSON
X-SETTL-Signaturesha256=<hmac>HMAC-SHA256 of the raw body
X-SETTL-Eventdeposit.confirmedThe event type
X-SETTL-DeliveryuuidUnique delivery ID
User-AgentSETTL-Webhooks/1.0Identifier

Retry policy

If your endpoint returns a non-2xx response, SETTL retries up to 3 times with exponential backoff: 1s → 3s → 9s.

Respond with HTTP 200 as fast as possible. Process the event asynchronously if needed — don't do slow work inside the webhook handler.

Event reference

deposit.confirmed

Fired when a customer's payment is confirmed on Solana.

{ "event": "deposit.confirmed", "merchant_id": "your-merchant-id", "timestamp": "2025-05-10T17:38:14.000Z", "data": { "reference_key": "4ioangUTMFqPWeY4S9aTYWx...", "amount": 25.00, "tx_signature": "3pP6cANTJX5hDu3XRydh...", "confirmed_at": "2025-05-10T17:38:14.000Z" } }

release.completed

Fired when the daily 6am release sends funds to your wallet.

{ "event": "release.completed", "merchant_id": "your-merchant-id", "timestamp": "2025-05-11T06:00:03.000Z", "data": { "gross": 25.00, "fee": 0.375, "net": 24.625, "tx_signature": "5mK9pBNT...", "released_at": "2025-05-11T06:00:03.000Z" } }

Verifying webhook signatures

Always verify the X-SETTL-Signature header before processing a webhook. Use the signing secret shown when you created the endpoint.

Node.js

const crypto = require('crypto'); function verifySettlWebhook(rawBody, signatureHeader, secret) { const expected = 'sha256=' + crypto .createHmac('sha256', secret) .update(rawBody) // rawBody must be the raw Buffer/string .digest('hex'); return crypto.timingSafeEqual( Buffer.from(signatureHeader), Buffer.from(expected) ); } // Express example app.post('/webhooks/settl', express.raw({ type: 'application/json' }), (req, res) => { const sig = req.headers['x-settl-signature']; const secret = process.env.SETTL_WEBHOOK_SECRET; if (!verifySettlWebhook(req.body, sig, secret)) { return res.status(401).send('Invalid signature'); } const event = JSON.parse(req.body); if (event.event === 'deposit.confirmed') { // Fulfil order using event.data.reference_key fulfillOrder(event.data.reference_key, event.data.amount); } res.status(200).send('OK'); });

Python

import hmac, hashlib, json from flask import Flask, request, abort app = Flask(__name__) SECRET = "your-webhook-signing-secret" def verify(payload_bytes, signature): expected = "sha256=" + hmac.new( SECRET.encode(), payload_bytes, hashlib.sha256 ).hexdigest() return hmac.compare_digest(signature, expected) @app.route('/webhooks/settl', methods=['POST']) def webhook(): sig = request.headers.get('X-SETTL-Signature', '') if not verify(request.data, sig): abort(401) event = request.get_json() if event['event'] == 'deposit.confirmed': fulfill_order(event['data']['reference_key']) return '', 200

Always use the raw request body (before JSON parsing) for signature verification. JSON serialisation can reorder keys and break the HMAC.
